# Maintained verifier and bounded deployment consumption

Reviewed and implemented 2026-09-07.

The verifier moves from Cosign 2.6.1 to the maintained 2.6.5 patch. The campaign additionally verifies the checked-in historical executable and provenance signatures with the new binary. JSON parsing rejects nonfinite constants; policy identity fields require bounded strings. Consumption validates the deployment record, rejects symlinked object directories and opens the executable with O_NOFOLLOW and O_NONBLOCK before checking regular-file type and size. A FIFO regression proves rejection without blocking.

## Why this scope

Cloud/ML infrastructure: artifact identity, release compatibility, authorization boundaries and fail-closed consumption. [Dated official hiring and release review](market-review-20260907.md). Other portfolio projects already cover distributed queues and cloud provisioning; this change addresses defects at this repository’s own boundary. No additional framework is required.

## Tradeoffs and limits

The 2.6.5 legacy-bundle security fix motivates maintenance; the detached-signature workflow is not asserted to have been affected. Cosign 3 changes defaults and is deferred because keyless/new-bundle behavior is outside this local-key contract. The owned object store assumes no hostile writer mutating the same opened inode during execution.

These are local CPU/Linux experiments with test-owned faults. No production traffic, cloud deployment, GPU execution, user count or service-level availability is inferred. Timing campaigns retain environment, raw samples and their original comparison method; this maintenance does not claim a performance improvement.
